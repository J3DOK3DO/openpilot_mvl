# Offline backup and recovery integrity

The verifier confirms an isolated host copy's listed regular file bytes, including known-good backup reference `sp-honda-dev-202608` at historical commit `a969e5e60debe4d7d5f5f6ec2935f5a97f2bd0d1`. It does not establish that this commit is installed on the device. Owner data is optional; known-good inventory is required. Symlinks, hardlinks, special files, path traversal, extra files, missing files, duplicate paths/keys, oversized manifests and mismatched hashes fail closed. Directory-relative `O_NOFOLLOW` file descriptors and before/after identity checks reduce path replacement races. A concurrent in-place writer still requires an immutable host snapshot for strong assurance.

The `--expected-manifest-sha256` value must come from an independently trusted channel. A digest bundled with the same backup is self-consistent but not independently trusted. No trusted signing key or pinned backup digest was provided, so `manifest_trust=EXTERNAL_HASH_REQUIRED` and `decision=NOT_INSTALLABLE` remain. Corrupt or unavailable backup, missing recovery metadata or a wrong known-good commit stops offline preflight before any device modification. No automatic device rollback is claimed.

Recovery decision: verify independent manifest anchor and complete host inventory; preserve known-good branch/commit; verify package provenance and target compatibility; prepare owner-controlled manual reinstall. If any input is missing or corrupt, HOLD and preserve evidence. Actual on-device backup, install, health and restoration require separate authorization and physical evidence.

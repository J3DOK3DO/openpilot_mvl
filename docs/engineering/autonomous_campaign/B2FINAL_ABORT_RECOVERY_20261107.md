# B2-Final abort and recovery

`qcom_b2final.py` has host-only fixture routines. `supervise_host_worker` checks policy throughout a bounded subprocess run and calls `stop_owned_process` on stale telemetry, ignition/motion/engagement, resource fault, quota signal, operator abort, connection loss, provider exception or timeout. It sends SIGTERM then SIGKILL only to a process group launched by the test controller; it does not target installed processes. If process identity or dedicated group cannot be proved, termination refuses to claim success.

`cleanup_host_fixture` is intentionally limited to exact `/tmp` run paths. It requires the run ID, source SHA, nonce, inode and device identity in `owner.json`, verifies no symlink or unexpected mount boundary through directory file descriptors, requires prior worker stop, preserves `evidence/` by default, and removes only regular files under the verified fixture. Missing directory cleanup is idempotent. Tests cover partial files, symlink injection, wrong owner, uncertain worker, evidence retention and repeat cleanup. A concurrent hostile same-user mutation or crash between preflight and deletion has no production safety claim; device cleanup requires a separately reviewed transaction and cgroup ownership proof.

On interruption, preserve logs and partial artifacts, record process and cgroup identity, and do not infer a compile PASS from a stopped Codex session. If ownership or mount identity is uncertain, leave the workspace untouched for manual reconciliation. No actual device cleanup, service restart, reset or rollback was performed.

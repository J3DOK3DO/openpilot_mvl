# B2-Final resource guards

The host fixture in `qcom_b2final.py` checks actual CPU/GPU temperature inputs (<70°C conservative stop), at least 512 MiB memory headroom, 2 GiB `/data` reserve, zero reported cgroup OOM events, zero GPU errors, fresh heartbeat, no unexpected process, no operator abort and a live controller connection. Missing or malformed inputs abort. The test supervisor launches and terminates only a subprocess it owns in a dedicated process group, records an abort reason and enforces a bounded timeout. Negative tests exercise thermal, memory, disk, quota, OOM, GPU, heartbeat, foreign process, connection loss, monitor exception and timeout. These are **host simulations**; no real Qualcomm GPU compiler was run.

A future device controller needs a cgroup v2 scope with verified `memory.max`, `memory.current`, `memory.peak`, `memory.events`, CPU affinity, `pids.max`, process-group/cgroup kill semantics and finite runtime. The prior temporary user scope confirmed a `MemoryMax=805306368` setting only; it did not demonstrate allocation failure, GPU memory accounting or isolation from driving services. GPU driver allocation and faults need separate observed controls. A monitor that checks `df` or temperature periodically cannot bound a fast allocation spike; a hard filesystem limit and kernel-enforced RAM/process limits are prerequisites.

The current host supervisor does not survive its own process death and cannot authenticate live device telemetry. A production guardian must be independently supervised and kill the whole owned cgroup if either monitor or control connection fails. That mechanism requires separate AGNOS 19.9 hardware proof and review. No design permits stopping Panda, stock ACC, warnings or installed driving services to make compilation fit.

# Campaign 2A abort and cleanup

`campaign2_host_guardian.py` is a **host-only /tmp fixture**. It admits an existing non-symlink /tmp directory and an owned regular Python fixture directly beneath it, starts the worker in a dedicated process group, requires controller heartbeats, and records a bounded result. Timeout, heartbeat loss, disconnect and abort terminate the whole live process group. The exited leader is kept unreaped until group inspection and termination are complete, preventing PID/PGID reuse during cleanup. Two regressions cover a leader that exits while a child remains and a child that ignores SIGTERM.

The first independent review found that the initial implementation could leave a child running after its leader exited. The reviewed fix is commit `947e326ec`; the first commit `9f16b4e8e` must not be used as proof. The fixture uses Linux /proc and `prctl` and is not a device controller. Parent-death handling is demonstrated only for a single direct worker leader. The reviewer **reproduced a guardian-crash failure with a descendant surviving**; descendants in new process groups or sessions are likewise unqualified. This blocks using the fixture as the required fail-safe device watchdog. No device cleanup was executed.

For a future approved device run, allocate a unique run ID and isolated destination; reject symlinks/traversal and unexpected ownership; preserve logs before deletion; stop only the owned compiler group; verify every member exited; remove only that run's temporary files after explicit scope authorization. Never delete `/data/openpilot`, source archives, backups or other runs. If interrupted, reconcile process identity and retained evidence before any cleanup. Until an independent device monitor and these cleanup boundaries pass, the device gate stays NO-GO.
